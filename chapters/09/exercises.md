# Chapter 09 | Exercises and knowledge checks

**1. Explain the gates.** Give one failure at each of structural resolution, behavioural execution and policy approval. A complete answer distinguishes an irrelevant or missing link, a failing or stale run, and an absent or unauthorised decision.

**2. Write an invariant and failing test.** Specify that a rejected conflict cannot alter an unrelated request. Use two requests, introduce a deliberate mutation of the second, and check that your test fails. Restore the implementation and rerun it.

**3. Verify the proposed extension.** Create the laboratory files in an approved working location. Compare `spec-v1.1.json` with the supplied Chapter 03 specification, generate the candidate and run the capture. Report the actual exit code and hashes rather than an expected result. Then introduce a dangling test name and check that validation rejects it.

**4. Review a change record.** A colleague says, “The version is `1.2`, so the change is accepted.” Identify the missing structural result, current execution evidence and authorised decision. Explain what the label and hashes do—and do not—establish.
